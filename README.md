# BIOGLOW Future Sim

Неофициальный браузерный тренажёр для **FIRST LEGO League BIOGLOW™ (сезон 2026-27), Future Edition**.

* Общее поле 2362×1143 мм с моделями обеих команд, миссии M01–M05 и Level Up «Invasive Attack», матч 2:30.
* Физика на Rapier: колёса на шарнирах с моторами, трение, навесное по-настоящему поднимает фишки.
* Две команды одновременно: у красных и синих свой робот, своя программа на Python, свой пульт или геймпад.
* Python с тем же API `legoeducation`, что у набора LEGO Education Computer Science & AI.
* Конструктор робота по правилам железа Future Edition, судья (штрафы, GP, Courtesy rule, история матчей),
  онлайн-игра по коду комнаты, геймпады и экранные джойстики.

Проект не официальный и не связан с FIRST и LEGO Group. Правила и очки взяты из официальных документов сезона
(Rulebook, Game Missions, Field Map, Game Update 01), но решения на соревнованиях принимают судьи.

## Запуск у себя

Нужен Python 3.11+ (ничего устанавливать не надо — только стандартная библиотека) и интернет:
библиотеки грузятся с CDN (three.js 0.170.0, Rapier 0.21.0, Skulpt 1.2.0, CodeMirror 5.65.16, шрифты Google).

```bash
cd fll-future-sim
python server.py
```

Откройте http://localhost:8080. Сервер отдаёт сайт из `public/` и WebSocket `/ws` для онлайна —
так работает всё, включая вкладку «Онлайн». Остановить — `Ctrl+C`.

Настройки сервера (переменные окружения):

| Переменная | По умолчанию | Что это |
|---|---|---|
| `PORT` | `8080` | порт |
| `HOST` | `0.0.0.0` | адрес (для доступа только с этого компьютера — `127.0.0.1`) |
| `LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error`, логи — строки JSON |
| `WS_PING_INTERVAL` | `20` | период ping для WebSocket, с |
| `WS_GRACE` | `20` | сколько секунд держать место отвалившегося участника |
| `WS_MAX_MESSAGE` | `1048576` | предел одного сообщения, байт |
| `TRUST_PROXY` | `0` | сколько своих прокси стоит перед сервером (см. ниже); на Render — `2` |
| `WS_MAX_CONNECTIONS` | `1000` | всего WebSocket-соединений на сервер |
| `WS_MAX_PER_IP` | `32` | соединений с одного адреса (IPv6 — с сети /64); школьный NAT — поднимите |
| `WS_ROOMS_PER_IP` | `12` | открытых комнат с одного адреса |
| `WS_ROOM_IDLE` | `1800` | комнату, где так долго (с) нет ни одного гостя, сервер закрывает |

Проверка: http://localhost:8080/healthz отвечает `ok`, `/stats` — счётчики комнат и соединений.

**Адрес клиента и `TRUST_PROXY`.** Лимиты «на адрес» (соединения, новые комнаты, попытки входа по коду)
считаются по адресу клиента. Заголовок `X-Forwarded-For` клиент может написать сам, поэтому при
`TRUST_PROXY=0` (по умолчанию: сервер смотрит в интернет напрямую, Docker, локальная сеть) он не используется.
За своим прокси (Render, nginx, балансировщик) задайте `TRUST_PROXY` = числу прокси: сервер возьмёт N-й адрес
справа в `X-Forwarded-For` — его дописал ваш прокси, подделать его нельзя. Проверка: в журнале строки `ws_open`
содержат `ip` и всю цепочку `fwd`. Если у разных игроков одинаковый `ip` (адрес прокси или CDN) — увеличьте
`TRUST_PROXY` на 1; если `ip` совпадает с тем, что можно вписать в `fwd` вручную, — уменьшите.

**Только статика (без онлайна).** Для разработки есть сервер без кэша — правки JS подхватываются сразу:

```bash
python tools/devserver.py        # http://localhost:8765 (порт можно передать аргументом)
```

Из `file://` сайт не работает (ES-модули так не грузятся) — нужен любой веб-сервер.

Полезные параметры адреса: `?pause` — открыть на паузе; `?room=КОД` — открыть вкладку «Онлайн» с уже
вписанным кодом комнаты (так выглядит ссылка-приглашение, кнопка «Ссылка» в комнате): гость сам выбирает команду;
`?room=КОД&role=red|blue|spectator` — сразу войти в комнату этой ролью (роль можно дописать к ссылке вручную).

## Выложить в интернет

### Render (Blueprint)

Render ищет `render.yaml` **в корне репозитория**. Выберите один из двух вариантов.

**Вариант А — репозиторий только из этого проекта** (в корне репозитория лежат `server.py`, `render.yaml`,
`public/`). Ничего менять не нужно:

```bash
cd fll-future-sim
git init -b main && git add . && git commit -m "BIOGLOW Future Sim"
git remote add origin https://github.com/ВАШ_АККАУНТ/bioglow-future-sim.git
git push -u origin main
```

**Вариант Б — `fll-future-sim` лежит папкой внутри большего репозитория.** Перенесите `render.yaml` из
`fll-future-sim/` в корень репозитория и в нём раскомментируйте строку `rootDir: fll-future-sim`
(путь к папке проекта от корня репозитория). Тогда Render запускает `python server.py` внутри этой папки.

```
ваш-репозиторий/
  render.yaml          # перенесён сюда, в нём rootDir: fll-future-sim
  fll-future-sim/
    server.py
    public/
```

Дальше для обоих вариантов:

1. Render → **New → Blueprint** → выберите репозиторий → **Apply**. Будет создан веб-сервис `bioglow-future-sim`
   (runtime python, план free, сборки нет, запуск `python server.py`, проверка здоровья `/healthz`, `TRUST_PROXY=2`).
2. Render сам задаёт `PORT`; сервер его читает. Сайт откроется по адресу вида `https://bioglow-future-sim.onrender.com`.
3. Проверьте `https://…onrender.com/healthz` (ответ `ok`) и в журнале сервиса строку `listen`.
   Нужен Python 3.11+ — версия Render по умолчанию подходит; закрепить свою можно переменной `PYTHON_VERSION`.

Что важно знать:

* Сайт открывается по HTTPS, поэтому онлайн-клиент сам подключается по `wss://…/ws` (на HTTP — `ws://`).
  Настраивать ничего не нужно; адрес другого сервера можно указать на вкладке «Онлайн» → «Сервер».
* В Blueprint задано `TRUST_PROXY=2`: перед сервисом Render стоят два прокси — Cloudflare (дописывает в
  `X-Forwarded-For` адрес игрока) и прокси Render (дописывает адрес Cloudflare), так что `fwd` выглядит как
  «адрес игрока, адрес Cloudflare». Проверьте по журналу (`ws_open`: `ip` и `fwd`), что `ip` — это адрес игрока
  и у разных игроков он разный, — см. «Адрес клиента и `TRUST_PROXY`» выше. Если в `ip` адреса Cloudflare
  (у всех игроков одни и те же несколько адресов) — увеличьте значение на 1.
* Бесплатный план **засыпает после 15 минут без запросов**; первое открытие после сна занимает около минуты.
  Пока в комнате идёт игра, трафик есть и сервис не засыпает.
* Комнаты хранятся в памяти. При перезапуске или деплое они пропадают, но клиенты сами переподключаются
  и пересоздают комнату с тем же кодом (хост и гости возвращаются за несколько секунд).
* Сервер на SIGTERM закрывает соединения кодом 1001 — клиенты переподключаются с паузой (backoff).

### Посещаемость и отчёт в Telegram

Сайт считает, сколько людей заходит за день, и после полуночи (по Актобе, UTC+5) бот присылает в Telegram отчёт:
посетителей за день и за 7 дней. Все дни для графика — по адресу `/visits.csv` (открывается в Excel и Google Таблицах).

* «Посетитель» — устройство: браузер раз в сутки шлёт `GET /api/visit`. Без cookies; сервер хранит только числа по дням,
  адреса не сохраняет. С одного адреса за день засчитывается не больше 60 заходов (класс за общим школьным NAT пройдёт,
  накрутка — нет). Ботов без JavaScript и открытия по `file://` не считаем.
* Сервер на Render засыпает и теряет память, поэтому счёт хранится в **закреплённом сообщении бота** в этом чате.
  Не удаляйте и не открепляйте его, иначе счёт начнётся заново (отчёты за прошлые дни останутся в чате).
* Чтобы отчёт приходил, даже если в полночь на сайте никого нет, GitHub Actions будит сервер в 00:03
  (`.github/workflows/wake.yml`). GitHub может опоздать с запуском до получаса; если в репозитории 60 дней нет коммитов,
  он отключает расписание: тогда включите его снова во вкладке Actions.

Настройка (один раз):

1. В Telegram откройте @BotFather → `/newbot` → получите токен бота.
2. Напишите своему боту любое сообщение, затем откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id": …}` — это ID чата.
3. Render → сервис `bioglow-future-sim` → Environment: задайте `TG_BOT_TOKEN` и `TG_CHAT_ID`, сохраните (сервис перезапустится).
   Часовой пояс отчёта меняется переменной `REPORT_TZ_OFFSET` (часы от UTC, по умолчанию 5).

Без `TG_BOT_TOKEN`/`TG_CHAT_ID` сайт тоже считает заходы, но только в памяти до перезапуска (видно в `/visits.csv`).
Проверка логики без сети: `python tools/test_visits.py`.

### Docker

```bash
docker build -t bioglow-sim .
docker run -p 8080:8080 bioglow-sim
```

Образ на `python:3.12-slim`, без root, с проверкой здоровья. Подходит для любого хостинга контейнеров.
Если перед контейнером стоит обратный прокси (nginx, балансировщик), добавьте `-e TRUST_PROXY=1`
(по одному на каждый прокси), иначе все игроки будут для лимитов «одним адресом» — адресом прокси.

### Статический хостинг

Папку `public/` можно выложить на любой статический хостинг (GitHub Pages, Netlify, Render Static Site и т. п.):
тренировка, матч, конструктор, судья, геймпады и Python работают. **Онлайн-комнатам нужен `server.py`**:
на статике вкладка «Онлайн» сообщит, что сервер недоступен; можно указать адрес своего `server.py`
в «Онлайн» → «Сервер» (`wss://ваш-сервер/ws`).

## Управление

### Клавиатура

Клавиши привязаны к физическому положению (`KeyboardEvent.code`), поэтому **работают и в русской раскладке**
(W = Ц, A = Ф, R = К и т. д.). Сначала щёлкните по полю.

| Клавиши | Действие |
|---|---|
| `W` `S` / `↑` `↓` | вперёд / назад (Driver) |
| `A` `D` / `←` `→` | поворот |
| `Shift` | медленно |
| `R` / `F` | рука на Single Motor вверх / вниз (Technician) |
| `G`, `Shift`+`G` | мотор Grand Tree вперёд / назад (Specialist) |
| `H` | Token Recycler: покоящиеся фишки из зоны Specialist |
| `Space` | запустить / остановить программу команды из шапки |
| `Esc` | остановить все программы |
| `P` | пауза, `Backspace` — сброс поля (только в тренировке) |
| `1`–`4` | камеры: 3D, сверху, база, за роботом |

Клавиатурой управляет команда, выбранная в шапке («Команда»). Флажок «Второй игрок на этой клавиатуре»
(вкладка «Миссии») отдаёт другой команде `I` `J` `K` `L`, `U`/`O` — рука, `Y` — дерево, `N` — Recycler,
правый `Shift` — медленно.

Пока работает программа команды, клавиши становятся **рычагами пульта** (`le.Controller`): Driver — `W`/`S`
левый, `↑`/`↓` правый; Specialist — `R`/`F` левый, `T`/`G` правый.

Мышь: фишки и робота можно перетаскивать (они упираются в борта и модели), колесо над роботом — поворот
(с `Shift` — по 1°), пустое место — камера. В режиме матча действуют правила «рук» (см. ниже).

### Геймпад

Xbox, PlayStation или совместимый, по USB или Bluetooth; после подключения нажмите любую кнопку
(браузер показывает геймпад только после нажатия). Нужен HTTPS или localhost; лучше всего — Chrome и Edge.
Назначение «геймпад → команда и роль» — вкладка «Миссии» → «Геймпады»: по умолчанию 1-й — Driver команды
из шапки, 2-й — её Specialist, 3-й и 4-й — другая команда.

* **Driver:** левый стик — вперёд/назад, правый стик — поворот (режим «Аркада» — всё на левом стике);
  `RT`/`LT` — рука; `LB` — медленно; крестовина — точная езда.
* **Specialist:** `RT`/`LT` или левый стик — мотор Grand Tree; `A` — Token Recycler.
* **Обе роли:** `Start` — программа своей команды, `Back` — вернуть камеру, `RB` — следующая камера.
  С программой стики — рычаги пульта своей роли.
* Вибрация (если есть): старт и конец матча, робот упёрся.

### Телефон и планшет

На сенсорном экране поверх поля появляются джойстики команды из шапки: левый — езда, правый — рука;
кнопки ▶/■, ½ (медленно), ▲/▼ (дерево), ♻ (Recycler). С программой джойстики — рычаги пульта,
кнопка D/S выбирает пульт Driver или Specialist. Режим (авто / всегда / выкл.) — вкладка «Миссии».

## Python: модуль `legoeducation`

Программы пишутся на вкладке «Код»: у каждой команды свой «Мой код», своя консоль и свои кнопки ▶/■;
«▶ обе команды» запускает обе программы одновременно. Программа и физика идут «в замке», поэтому результат
не зависит от скорости 1×/4× и частоты кадров.

```python
import legoeducation as le
robot = le.DoubleMotor(); robot.connect()                    # ходовая робота
tree  = le.DoubleMotor(); tree.connect(device_name='tree')   # мотор Grand Tree
arm   = le.SingleMotor(); arm.connect()                      # навесное (Technician tool)
eye   = le.ColorSensor(); eye.connect()                      # датчик цвета, смотрит вниз
pad   = le.Controller();  pad.connect()                      # пульт Driver
spec  = le.Controller();  spec.connect(device_name='specialist')

robot.movement_move_for_degrees(720, speed=50)
robot.movement_turn_for_degrees(90, direction=le.MOVEMENT_TURN_DIRECTION_RIGHT)
robot.movement_move_tank(40, 60); robot.movement_stop()
robot.motor[le.MOTOR_LEFT].position ; robot.imu_device.yaw
arm.motor_run_for_degrees(270, speed=60)                     # рука +90° (передача 1:3)
eye.sensor.color ; eye.sensor.reflection
pad.sensor.leftPercent ; spec.sensor.rightPercent
```

* Лимиты железа Future Edition проверяются в `connect()`: один Double Motor ходовой + Double Motor дерева,
  один Single Motor, один Color Sensor, два пульта (Driver и Specialist). Лишнее устройство — понятная ошибка.
* Ошибка подсвечивает строку вашей программы; `exit(1)` считается ошибкой, `exit()` — нормальным завершением.
* Примеры в списке: квадрат, Central Haven, танковое управление с пульта, датчик цвета, мотор Grand Tree,
  пульт Specialist, точный поворот по гироскопу. Выбор примера не стирает «Мой код».
* Yaw растёт при повороте влево. Числовые значения констант `le.*` в документации не опубликованы —
  сравнивайте с константами, а не с числами.

Программу можно перенести на настоящего робота: `pip install legoeducation` (Python 3.14+),
в `connect()` укажите цвет и номер своей Connection Card.

## Конструктор робота

Вкладка «Конструктор»: колёса (44, 56, 62.4, 88 мм), колея, рама, опора, балласт, датчик цвета и навесное
(ковш, захват, молоток, толкатель или ничего). Шесть готовых роботов, 3D-превью, вид сверху в зоне Technician,
проверка массы, габарита, высоты, центра масс и набора железа. Конфигурацию можно сохранить в браузере,
экспортировать в JSON или передать коротким кодом. «Применить» пересобирает робота команды:
вне матча — всегда, во время матча — только когда робот целиком в зоне Technician.
Онлайн-гость отправляет робота хосту, тот проверяет его по тем же правилам и пересобирает.

| M01 Mighty Microbiomes | 20 за ключевой вид в Young Forest / Grand Tree / Hollow Tree (до 3 в каждом); +40, если в Young Forest ≥ 3 и королева соперника сбита |
| M02 Roots of Renewal | 5 за ресурс в base Grand Tree (1 ресурс стоит там на старте); 10 за ресурс в canopy chamber (до 15, только через дерево) |
| M03 Cave Waterfall | 5 за каждый ключевой вид через водопад (по счётчику, до 50) |
| M04 Rainforest Awakening | 30 — виды выпущены из Nest; 20 — ресурсы выпущены из Hollow Tree |
| M05 Central Haven | 5 за каждую фишку целиком в центральном круге — обеим командам |
| Level Up: Invasive Attack | 20 за добавленный инвазивный вид (до 5); 10 за каждый в зоне сдерживания |

**Матч.** Режим «Матч» → роботы в зонах Technician → «Старт»: проверка (робот целиком в зоне Technician,
высота ≤ 20.3 см, железо по правилам), отсчёт 3 с, 2:30 по времени симуляции. Скорость и пауза заблокированы.
На 0:00 программы и моторы останавливаются, ввод замораживается, 2 с физика «досчитывает» фишки, затем счёт
фиксируется. Флажок «по старту матча» запускает программу команды по сигналу старта.

**Штрафы** (вкладка «Судья», правило 21 и Game Update 01): 1-й −10, 2-й ещё −20, 3-й — счёт матча 0;
ниже 0 счёт не опускается. Судья может штрафовать и за явное нарушение или злоупотребление правилами.
Каждый штраф записывается в «Протокол» со временем матча. Gracious Professionalism записывается на матч
и в очки не входит (шкала GP в документах не указана — в симуляторе допущение 2/3/4, 0 — не явилась).

**Courtesy rule.** Застрявший робот возвращается в зону Technician; фишки, которые он вёз, снимаются из игры,
толкаемые остаются. Со 2-го раза за матч — предупреждение о возможном злоупотреблении.

**Руки** (режим матча, мышью играет команда из шапки): Driver робота не трогает; Technician берёт робота
и фишки, только когда они целиком в его зоне; Operator — фишки целиком в своей зоне и K/R хотя бы частично
в retrieval zone; из корней (mangrove roots) — только инструментом; Specialist отправляет фишки в Recycler.
Трогать можно только покоящиеся фишки, не касающиеся робота. Режим «Отдать судье» снимает предмет из игры.

**Флаги вмешательства.** Подсказки судье, когда робот касается робота, моделей или фишек соперника на его
половине или стоит в его зоне игроков. Сами они не штрафуют — решает судья.

**История матчей.** Итог каждого матча попадает в историю; после согласования с командами его можно
подтвердить. Рейтинг — по **среднему** всех матчей команды в зачёт (минимум 3), выгрузка в CSV для Excel.

## Онлайн

Хост создаёт комнату (вкладка «Онлайн») и говорит 4-символьный код или отправляет ссылку. Гости входят
за красных, синих или зрителями (до 6). Компьютер хоста считает физику и программы обеих команд;
гость управляет своим роботом клавиатурой, геймпадом или джойстиками, «Запустить» отправляет его программу
хосту, консоль приходит обратно. До старта матча программа гостя ждёт у хоста и запускается по сигналу старта.
Матч, сброс поля, штрафы и скорость — у хоста; гости видят тот же счёт, штрафы и итог.
При обрыве связь восстанавливается сама, перезагрузка вкладки возвращает на своё место. Если то же место
открыть во второй вкладке (например, «Дублировать вкладку»), место переходит к новой вкладке, а старая
сообщает об этом и возвращается к локальной игре.

Робота гостя хост проверяет по пределам конструктора и правилам Future Edition; в браузере хоста он не
сохраняется, и после закрытия комнаты хосту возвращается его робот (кроме идущего матча). Очень частый `print`
в программе гостя доходит до него не весь — пропущенное отмечается строкой «… пропущено фрагментов вывода».

Защита сервера: лимиты на соединения, новые комнаты и попытки входа по коду с одного адреса; зритель может
слать хосту только служебные сообщения; комната без гостей закрывается через 30 минут; код комнаты,
которую ждут гости после обрыва хоста, 2 минуты может занять только сам этот хост.

## Известные ограничения

* **Модели поля упрощённые.** Официальных 3D-файлов сезона нет; модели построены по Field Map (±2 см).
* **Колёса проскальзывают,** если робот упёрся в борт или другого робота: заклинивание ходовой не сообщается,
  команды завершаются по энкодеру, времени или таймауту поворота. Заклинивание руки в упоре определяется.
* **Пример «Central Haven» рассчитан на робота с ковшом.** С отвалом он набирает 5 очков, с захватом и молотом — 0.
  Примеры «квадрат», «гироскоп» и «цвет» работают со всеми пресетами. Длинный робот с ковшом не разворачивается
  внутри зоны Technician — примеры сначала выезжают из неё.
* **Повторяемость.** «Сброс поля» пересоздаёт физический мир, поэтому прогон после сброса совпадает с прогоном
  после загрузки страницы. Но результат, где ковш толкает кучку фишек, чувствителен к мелким различиям во времени
  команд, и очки M05 у примера «Central Haven» иногда отличаются на одну фишку.
* **Датчик цвета** висит в 0.8 см над ковриком и толкает фишки, а не проезжает над ними.
* **Рука под нагрузкой:** удерживая поднятый груз, мотор тратит ~23 % мощности, а колёса медленно доворачиваются
  (~5° за 30 с). Фишка, на которую опирается вес робота, проседает в коврик на 1–2 мм.
* **Инструмент Operator** — упрощённая модель (лоток-катапульта у барьера и крючок внутри зоны Operator),
  а не собранный из деталей инструмент.
* **Python гостя выполняется во вкладке хоста** (Skulpt работает в основном потоке). Ограничители не дают программе
  занять больше 1 с подряд, но плохая программа гостя может на эти доли секунды притормозить вкладку хоста.
* **Запас 5 K на Grand Tree** стоит на высоте 31 см — роботу недоступен (как на настоящем поле).
* **Онлайн:**
  * если вкладка хоста в фоне, симуляция идёт от таймера в Web Worker (~60 тиков/с), но браузер может её
    дополнительно притормозить в режиме энергосбережения — лучше держать вкладку хоста открытой;
  * изменения, сделанные хостом на паузе (штрафы, Courtesy rule), доходят до гостей с ключевым кадром — до 1 с;
  * у гостя не обновляется телеметрия угла руки, а ошибка удалённой программы не подсвечивает строку в редакторе
    (номер строки есть в консоли);
  * GP, названия команд и история матчей хранятся только в браузере хоста.
* **Судья:** возврат очков, потерянных из-за вмешательства соперника, не автоматизирован — это решение судьи.
  Флаги строятся по контактам, поэтому толкание у центральной линии может дать ложный флаг.
* **Геймпады и джойстики** проверены на эмулированных устройствах; раскладки редких геймпадов могут отличаться.
